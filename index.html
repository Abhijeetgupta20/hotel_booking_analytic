💡 Business Insights

All insights below are derived directly from computed KPIs — no manual interpretation or fabricated figures.

1 — More Than a Quarter of Bookings Are Lost
27.52%
24,005 out of 87,224 bookings did not result in a completed stay. 22,992 were pre-arrival cancellations; 1,013 were no-shows. One in four bookings produces no revenue.
2 — City Hotel Cancels 6.6 pp More Than Resort
28.69% vs 22.70%
City Hotel (narrow cancel rate) vs Resort Hotel. The 6.6 pp gap on 53,270 City Hotel bookings represents roughly 3,190 additional lost bookings compared to the Resort rate.
3 — Online TA: Most Volume, Highest Cancellation
59.1% vol · 35.38% cancel
Online TAs drive 51,552 bookings (59.1%) but cancel at 35.38%. Direct bookings cancel at only 14.74%. Shifting 5% of OTA to direct would save an estimated 532 cancellations per year.
4 — Cancelled Bookings Made 35 Days Earlier
105.8 days vs 70.2 days
Average lead time for cancelled bookings vs confirmed stays. Long lead time is a measurable, early-warning signal. Bookings over 90 days out are at significantly higher cancellation risk.
5 — Repeat Guests Cancel at Less Than ⅓ the Rate
7.73% vs 28.31%
Repeat guest broad cancel rate vs first-time guests — a 20.58 pp gap. Only 3.9% of guests (3,363) are repeat visitors. Increasing this share would meaningfully stabilise confirmed bookings.
6 — Resort Reassigns Rooms Almost Twice as Often
20.64% vs 11.23%
Resort Hotel vs City Hotel mismatch rate. 95.31% of mismatches are upgrades — but 609 guests (4.69%) received a downgrade, representing a real service-quality risk.
7 — August Is Both Busiest and Riskiest Month
11,238 bookings · 32.19% cancel
August is the single busiest month and simultaneously has one of the highest cancellation rates. Overbooking strategies must account for this combined pressure.
8 — More Requests = Fewer Cancellations
33.25% → 5.56%
Cancel rate drops from 33.25% (0 special requests) to 5.56% (5 requests). More special requests signal a more committed guest — a useful feature for cancellation-risk modelling.

📁 Project Structure & How to Run

FOLDER STRUCTURE

hotel_booking_analytics/ ├── data/raw/ ← hotel_bookings.csv (not in Git) ├── data/processed/ ← cleaned CSV + report ├── db/ ← SQLite database (not in Git) ├── dashboard/ │ └── app.py ← Streamlit + Plotly ├── docs/ │ ├── dataset_info.md │ └── business_insights_report.md ├── notebooks/ ← Jupyter EDA notebooks ├── outputs/ ← 23 PNG charts ├── sql/ ← 14 SQL query files ├── src/ │ ├── data_loader.py │ ├── data_cleaning.py │ ├── eda.py │ ├── db_setup.py │ ├── run_sql_analysis.py │ ├── kpi_calculator.py │ └── generate_report.py ├── tests/ ← 95 unit tests (all pass) ├── requirements.txt └── README.md

HOW TO RUN

# 1. Install dependencies pip install -r requirements.txt # 2. Place hotel_bookings.csv in data/raw/ # (download from Kaggle — link above) # 3. Clean the dataset python src/data_cleaning.py # 4. Generate EDA charts python src/eda.py # 5. Build SQLite database python src/db_setup.py # 6. Run SQL analysis + cross-checks python src/run_sql_analysis.py # 7. Generate business report python src/generate_report.py # 8. Launch interactive dashboard streamlit run dashboard/app.py # 9. Run all 95 unit tests python -m pytest tests/ -v

TECH STACK
